1. 요청하신 작업

빈 공정 폴더에, 나중에 개선한 모듈과 비교할 수 있는 최소 파이프라인을 구현했습니다. 정확도 개선과 비용 최적화 기능은 추가하지 않았습니다. 당시 실행에서는 Haiku 4.5를 기본 모델로 사용했습니다.

2. 구현한 흐름

3. 실제 실행 결과

원본 RFP 대신 실행 점검용 합성 문서 두 개를 사용했습니다.

질문: 새봄연구소 사업의 예산과 필수 기능은 무엇인가요?

실제 Haiku 응답

새봄연구소 사업의 예산은 3000만 원이며, 필수 기능은 회의실 예약, 예약 취소, 사용 현황 조회입니다.

근거: office.txt:c0

12 / 12파이프라인 오프라인 검사
11 / 11키 설정·이전 형식 호환 검사
1회실제 Haiku 생성 성공
661 / 84공급자 응답의 입력 / 출력 토큰

Python 컴파일과 Git 공백 검사도 통과했습니다. 위 토큰 수는 API 응답에서 확인한 값이며, 채팅 입력 크기나 청구액이 아닙니다.

4. 실패하거나 확인하지 않은 부분

OpenAI는 첫 임베딩 요청에서 HTTP 401 인증 오류로 중단됐습니다. GPT-5 mini·nano 생성 단계에는 도달하지 못했습니다. 설정과 코드는 남겼지만 실제 동작 확인은 끝나지 않았습니다.

정확도 평가·원본 RFP 100문서 실행·실제 PDF/HWP 전체 검증은 하지 않았습니다. 스캔 PDF의 OCR·HWPX·표 구조 보존·CSV 메타데이터 연결은 미구현입니다. 키 입력창은 합성 검사와 실행을 확인했으며 실제 창의 시각 검수는 하지 않았습니다.

5. 결정과 이유

당시 기본 모델은 요청에 따라 Haiku 4.5로 정했습니다. OpenAI 인증 없이 작동하도록 검색은 로컬 TF-IDF로 구성했습니다. 단어 일치만으로 검색하므로 한국어 조사와 동의어 처리에 한계가 있습니다.

재순위·질문 분류·대화 기억·답변 내용 검증·품질 평가·LangSmith·웹 화면은 비워 두었습니다. JSON과 근거 ID의 형식만 확인합니다. 각 담당자가 공통 입력·출력을 유지하며 기본 모듈을 바꿀 수 있습니다.

6. 당시 실행 경로를 명시한 재현 명령과 다음 단계

아래 명령은 당시 사용한 Haiku + 로컬 TF-IDF 경로를 명시합니다. 색인과 질문 벡터화는 로컬에서 처리하며, 답변 생성에는 Anthropic API 사용량이 발생합니다. 유효한 ANTHROPIC_API_KEY가 필요합니다. OpenAI 임베딩과 GPT-5 mini는 별도 configs/openai.toml을 지정해야 하며 실제 성공은 미확인입니다.

.venv/Scripts/python -m rfp_rag --config configs/haiku.toml --data-dir examples/synthetic --build --ask "새봄연구소 사업의 예산과 필수 기능은 무엇인가요?" --usage

실제 문서는 로컬 data/raw/에 준비합니다. 문서를 바꾸면 --build로 다시 색인을 만드세요. 원본·키·본문·색인은 Git에 올리지 않습니다.
